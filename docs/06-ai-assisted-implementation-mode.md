# AI-assisted implementation mode

The learner acts as an automation lead. Codex or Claude Code writes and changes the code. The learner owns the business result and must be able to direct, review and operate the system.

## Learn these skills

- Find repeated work, delays, errors and missing information.
- Decide whether to use a dashboard, fixed workflow, one AI step or a small agent.
- Define the trigger, inputs, rules, exceptions, output and owner.
- Write implementation prompts with clear boundaries and acceptance tests.
- Check calculations, source links, permissions, failure states and recovery.
- Run a small pilot, compare results and prepare the handover.
- Ask a coding agent to explain technical choices in plain English.

## Delegate these tasks

- Project setup and dependency installation.
- Writing application code, API clients, database migrations and UI components.
- Writing and running automated tests.
- Refactoring, packaging and deployment commands.
- Producing technical diagrams and first drafts of runbooks.

Delegation does not remove responsibility. The learner must decide what the system should do, provide the rules, review the result and know what happens when it fails.

## Use this implementation loop

1. **Discover:** observe the current work and record volume, time, owners and problems.
2. **Choose:** compare the likely value, data readiness, rule clarity and error impact.
3. **Map:** draw the current flow and the improved flow, including exception paths.
4. **Specify:** write the business rules, permissions, output and acceptance tests.
5. **Prompt:** direct Codex or Claude Code using the brief and repository context.
6. **Review:** trace important results to their source and test failure cases.
7. **Pilot:** use a small approved group and compare old and new results.
8. **Operate:** assign an owner, monitor failures and keep recovery instructions current.

## What counts as learning evidence

- A ranked opportunity map with reasons.
- A complete process and exception map.
- A build brief another agent can implement without guessing key rules.
- Versioned build, review, fix and handover prompts.
- Acceptance-test results and a record of failed cases.
- A demo that explains the result, limits and recovery path.
- A pilot report that uses measured outcomes.

Reading code is optional. Learn a technical detail when it helps you make a decision, find a risk or verify a result. Do not spend course time memorising syntax unless you choose to.

## How to read the remaining weekly missions

When a mission says “write,” “build,” “implement,” “add” or “fix,” direct Codex or Claude Code to do the code work from your brief. Your task is to supply the business rules and constraints, review the proposed plan, inspect the result, run or observe the checks, and decide whether the evidence is good enough.

Technical topics such as Python, SQL, JSON, APIs and web frameworks are implementation tools. Learn what they are for, what can fail and what proof to request. You do not need to memorise their syntax. A tutor must not turn these missions into programming lessons unless you ask.
